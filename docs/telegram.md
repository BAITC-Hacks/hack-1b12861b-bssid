# Подключение Telegram Mini App

Подготовлен адаптивный локальный интерфейс. Официальный `telegram-web-app.js` сохранён в `public/vendor/`, он загружается с того же сервера; CDN не используется. В Telegram приложение вызывает ready/expand и задаёт цвета оболочки. В обычном браузере работает тот же экран. Проверка внутри реального Telegram и публикация пока не выполнялись: пользователь выбрал локальный вариант.

## Дальнейшие действия владельца

1. Подготовить домен и сервер с HTTPS-сертификатом. Развернуть проект и установить зависимости, выполнить `python start.py --batch-only` для создания проверенных выгрузок.
2. Для публичного просмотра задать `HOST=0.0.0.0` и `PORT` через окружение или `server/.env` (пример рядом). В этом режиме API пересчёта отключён. Перед сервером можно поставить HTTPS reverse proxy; либо задать `HTTPS_KEY` и `HTTPS_CERT` для встроенного HTTPS. Пути к ключам относятся к серверу владельца и не включаются в репозиторий.
3. Создать/выбрать бота через @BotFather и в настройках кнопки меню или Mini App указать HTTPS URL развернутого интерфейса. Серверу просмотра токен бота не нужен.
4. Открыть кнопку в Telegram, проверить поиск gid, мобильную карточку и масштабирование графа. Браузерные тесты не заменяют проверку в Telegram WebView.

Этот вариант — экран просмотра обезличенного демонстрационного датасета. Telegram initData не используется как доказательство аутентификации и на сервере не проверяется. Для закрытой банковской установки потребуется отдельная аутентификация/авторизация на прокси либо проверка подписи initData и список допущенных аналитиков. Не открывать локальный режим с доступным пересчётом наружу через прокси. HTTPS-конфигурация и подключение бота требуют действий владельца и не включены в локальную проверку.
