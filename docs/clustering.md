# Louvain: методика этапа 3

Используется `python-louvain==0.16`. [API библиотеки](https://python-louvain.readthedocs.io/en/latest/api.html) принимает ненаправленный граф, поэтому строится отдельная проекция: вес пары — сумма sum_kzt в обоих направлениях. Положительные суммы не нормализуются и не заменяются количеством транзакций. Изолированные узлы сохраняются отдельными сообществами. Исходный направленный граф используется для анализа потоков и последующих этапов.

## Выбор разбиения

Настройки находятся в `python/config/clustering.json`:

- `resolution=1.0`; `random_states=[42,43,44,45,46]`.
- Выбор максимальной взвешенной модульности среди пяти запусков **при той же resolution**; при равенстве — первый запуск. Между разными resolution максимум не сравнивается.
- Номера кластеров назначаются по убыванию размера, затем по минимальному gid. Порядок узлов и рёбер перед алгоритмом сортируется для воспроизводимости.
- Ориентир 8 сообществ с n_seed>1 — только диагностика. `reference_deviation=True`, если отличие больше `reference_tolerance=3`; параметр не используется для подгонки разбиения.

## Устойчивость

Общая оценка — adjusted Rand index (ARI) для каждой пары запусков; 1 означает одинаковое разбиение независимо от номеров кластеров.

Для каждого выбранного кластера в каждом другом запуске находится сообщество с максимальным Jaccard = размер пересечения / размер объединения участников. Худшее из этих совпадений записывается в `stability_min_jaccard`; `is_stable=True` при значении ≥0.8. Это диагностический критерий устойчивости к случайному порядку обработки узлов, не доказательство устойчивости сети во времени. Для одиночного изолированного узла он также равен 1.

Дополнительно всегда выполняются пять запусков для каждой resolution 0.5, 0.75, 1.25, 1.5 и 2.0. Диагностика сохраняется в `clustering_diagnostics.json`; по её результатам resolution автоматически не меняется. Полный запуск включает 30 разбиений.

## Поля clusters.csv

После подключения этапа 6 `clusters.csv` содержит строго шесть обязательных колонок; все перечисленные ниже дополнительные признаки сохранены в `clusters_detailed.csv` и `clusters.json`.

Обязательные поля: `cluster_id, n_nodes, n_seed, sum_kzt_internal, top_gids, hypothesis`.

- `sum_kzt_internal`: сумма исходных направленных рёбер, оба конца которых внутри кластера; каждое ребро учитывается один раз.
- `sum_kzt_incoming`, `sum_kzt_outgoing`: переводы между данным кластером и другими. Это не внешние банковские потоки за пределами выборки.
- `top_gids`: JSON-массив строк, до пяти участников по убыванию in_kzt+out_kzt **во всём наблюдаемом графе**. При равных оборотах — по gid. Это ранжирование по обороту, не по предполагаемой роли.
- `internal_share`: internal / (internal + incoming + outgoing), при отсутствии потоков 0.
- `n_depth4`: количество участников на четвёртом колене.
- `stability_min_jaccard`, `is_stable`: оценка устойчивости состава.

Проверяется: сумма n_nodes равна числу узлов, сумма n_seed равна числу seed, внутренние потоки плюс межкластерные исходящие равны обороту графа; сумма межкластерных входящих равна сумме межкластерных исходящих.

## Правила текстовых гипотез

Применяется первое подходящее правило:

1. Нет наблюдаемых потоков → изолированный фрагмент.
2. internal_share≥0.8 → преимущественно внутренний оборот.
3. outgoing>1.5×incoming → передача средств другим сообществам.
4. incoming>1.5×outgoing → получение средств из других сообществ.
5. Иначе → смешанный обмен между сообществами.

В каждом тексте указаны число узлов и seed, внутренний оборот, вход, выход и число узлов четвёртого колена. Правила описывают наблюдаемые потоки и состав; они не присваивают клиентские роли и не утверждают незаконное назначение группы. Граница четырёх колен и неполнота входящих seed сохраняют значение при интерпретации.

## Полученный результат

Выбран random_state=45 при resolution=1.0: **90 кластеров**, модульность **0.8611**. Во всех пяти основных запусках получается **8 кластеров с более чем одним seed**. Остальные сообщества имеют ноль или один seed, включая изолированных клиентов; они сохранены в выгрузках.

Минимальный ARI — **0.9241**, средний — **0.9480**. Из восьми сообществ с несколькими seed только **5** проходят строгий порог Jaccard≥0.8. Кластеры 3, 14 и 37 имеют минимум Jaccard около 0.753, 0.223 и 0.059 соответственно: совпадение числа сообществ не означает устойчивость каждого состава.

При resolution 0.75–2.0 число сообществ с несколькими seed находится в диапазоне 8–9; при 0.5 — 8–14, что показывает чувствительность этой настройки. Базовое значение 1.0 сохранено. Ориентир по количеству подтверждён, устойчивость состава всех восьми не подтверждена.
